# 第一篇 · Skill 接口

> 来源：文档 1（v1.0 列表/字段/分类/架构）+ 文档 4（v1.1 详情/安装）+ 文档 5（代码落点）。

## 〇、对接前必读（结论先行）

1. **服务端只认 3 个参数**：`name`、`page_number`、`page_size`。你想要的 `category`、`sort`、`tags` 它全当空气。
2. **两个硬墙**：`page_size` 只能 `1–100`（否则 `400`）；**全量只能取 2400 条**（第 25 页起 `403 QuotaLimitExceed`）。但接口 `total` 字段却写 `76781`/`77007`——**这个数字不可信，永远别拿它做分页/计数**。
3. **`name` 不是过滤器**：它只是个"相关性提示"。无命中时服务器会退回默认热门列表（且 `total` 不变），返回的条目里**可能根本不含你搜的词**。要做精确过滤，必须**客户端二次过滤**。
4. **详情接口路径是坑**：单条详情走 `GET /api/v1/skills/<id>`（注意是 `/api/v1/` 而非 `/openapi/v1/`）；`/openapi/v1/skill/<id>`（单数）实测 **404**。详情**不直接回传 SKILL.md 文本或 zip 直链**，安装靠详情里的 `source_url` 回 GitHub 取 raw SKILL.md。

> 一句话对接策略：**把服务端当"裸数据泵"（最多 2400 条），所有查询、分类、排序、计数都在你本地做。**

## 二、列表查询请求参数

| 参数 | 类型 | 必填 | 默认 | 合法范围 | 说明 / 实测行为 |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `name` | String | 否 | `""` | 任意字符串（建议 URL 编码） | **弱相关性提示，非严格过滤**。命中时靠前排，但响应仍可能夹带无关项；`total` 不受其影响。 |

## 四、错误码与异常处理（列表）

统一结构：`{"success":false,"request_id":"...","code":"<错误码>","message":"<说明>"}`。

| HTTP | code | message（样例） | 触发条件 | 客户端应对 |
| :--- | :--- | :--- | :--- | :--- |
| 400 | `InputParameterError` | `page_size should be between 1 and 100` | `page_size` 越界 | 校验入参，钳制到 1–100 |
| 400 | `InputParameterError` | `page_number should be greater than 0` | `page_number ≤ 0` | 校验入参，最小为 1 |
| 400 | `InputParameterError` | `invalid request body` | 参数非整数/格式错 | 校验类型 |
| 403 | `QuotaLimitExceed` | `Quota limit exceeded: quota limit exceed 2400 skills` | 累计返回 skill 达 2400（约第 25 页） | **停止翻页**，改用本地索引 |
| 200 | — | （正常但 `total` 失真） | `name` 无命中 | 客户端按词二次过滤，勿信 `total` |

> 建议：所有调用包一层「请求 → 解析 `success` → 非 success 取 `code`/`message` 抛异常」的处理；遇到 `QuotaLimitExceed` 立即终止翻页循环。

## 七、一键安装（Install）· 基于 source_url

安装原理：详情接口不直接回传 SKILL.md，但 `source_url` 指向 GitHub 仓库 → 拼 GitHub raw SKILL.md → 解析 frontmatter。

### 7.1 安装流程

```
用户粘贴 ModelScope skill 详情页 URL
   │
   ▼
detectPlatform(url) → 'modelscope'
   │
   ▼
从 URL / 详情接口取出 id（或 source_url）
   │
   ▼
优先用 source_url 拼 GitHub raw SKILL.md：
   https://raw.githubusercontent.com/<owner>/<repo>/<branch>/.../SKILL.md
   │ （实测可达，返回 text/plain，含 frontmatter: name / description）
   ▼
解析 SKILL.md frontmatter → 安装完成
```

## 九、客户端索引架构 / 交付物 / 最佳实践

### 9.1 推荐架构（客户端索引模式）

由于服务端几乎不做查询，推荐如下分层：

```
┌─────────────────────────────────────────────┐
│  你的应用 / 前端                              │
│   搜索框 · 分类下拉 · 排序 · 分页             │
└───────────────┬─────────────────────────────┘
                │ 本地查询（name 模糊 / category / sort / 分页 / 计数）
                ▼
┌─────────────────────────────────────────────┐
│  本地索引层（skills_index）                   │
│   - 2400 条 skill 的轻量副本                  │
│   - 支持精确过滤、排序、分页、真实计数         │
└───────────────┬─────────────────────────────┘
                │ 仅首次 / 定时刷新时调用
                ▼
┌─────────────────────────────────────────────┐
│  ModelScope API（裸数据泵）                   │
│  GET /openapi/v1/skills?page_number=1..24     │
│  遇 403 QuotaLimitExceed 即停                  │
└─────────────────────────────────────────────┘
```

**要点**：
- 索引仅在「首次部署」或「定时刷新」时构建一次，运行期查询全走本地，零延迟、零配额消耗。
- 单次构建最多翻 24 页（2400 条），务必在拿到 `403 QuotaLimitExceed` 时**立即停止**，避免无效请求。

### 9.2 调用示例

```bash
# 原始 curl（取第一页）
curl -s "https://www.modelscope.cn/openapi/v1/skills?page_number=1&page_size=100" \
  -H "Accept: application/json"
```

```python
import urllib.request, json

def fetch_page(pn, size=100):
    url = f"https://www.modelscope.cn/openapi/v1/skills?page_number={pn}&page_size={size}"
    req = urllib.request.Request(url, headers={"Accept": "application/json"})
    with urllib.request.urlopen(req, timeout=30) as r:
        return json.loads(r.read())

all_skills, pn = [], 1
while pn <= 24:                      # 最多 24 页（配额墙）
    d = fetch_page(pn)
    if not d.get("success"):
        print("停止：", d.get("code"), d.get("message"))
        break
    batch = d["data"]["skills"]
    if not batch:
        break
    all_skills += batch
    pn += 1
print("采集到", len(all_skills), "条")
```

### 9.4 最佳实践 & 注意事项

1. **永远不要相信 `total`**：它恒为失真值（两版实测 76781 / 77007），既不代表可访问量，也不代表 `name` 命中数。真实条数 = 你本地索引的长度。
2. **`name` 必须客户端二次过滤**：拿到响应后，自行判断条目是否真的包含搜索词；否则会混入无关项。
3. **配额是硬墙**：单次会话/口径下累计返回 2400 条即封顶。构建索引时分页到 `403` 立即停，不要重试死循环。
4. **未知参数被忽略**：别指望服务端会帮你校验或实现未文档化的过滤。
5. **缓存索引**：索引是 2026-08-16/17 快照；数据变化不频繁，建议每日/每周重跑 `crawl_skills.py` 刷新即可，运行期查询走本地。
6. **容错**：网络超时重试 2–3 次并退避；解析前先判 `success` 与 HTTP 状态码。
7. **扩展思考**：若业务需要全量（>2400）或按分类服务端过滤，需向 ModelScope 申请**更高配额或鉴权 token**——当前公开端点不具备该能力。

# 第二篇 · MCP 接口

> 来源：文档 2（v1.0 列表/字段/分类/架构）+ 文档 3（v1.1 详情/安装/真实抽样）+ 文档 5（代码落点）。

## 〇、对接前必读（结论先行）

1. **方法是 PUT，不是 GET**：传参走 **JSON Body**，不是 Query String。
2. **鉴权"名义必填、实际宽松"**：不传 token 也能读（返回 200 数据），但传**假** token 会 `401 InvalidAuthentication`。官方要求 `Bearer` 令牌，建议生产环境带上。
3. **服务端过滤是真的，且 `total_count` 可信**（与 skills 接口相反！）：`search` / `filter.category` / `filter.is_hosted` 均生效，`total_count` 反映真实命中数（实测 **9959**）。
4. **`filter.tag` 是空操作**：实测传任何 tag（真实或捏造）都返回 `total_count` 全部，不起过滤作用。对接时**不要依赖 tag 过滤**。
5. **配额墙**：匿名口径下 `page_number × page_size ≤ 100`（超出 `403 QuotaLimitExceed`）；翻页/全量必须带**有效 Bearer token**。
6. **分类数据有脏数据**：源数据里大量分类带**前导空格**（` developer-tools`）、还有大小写变体（`Search`/`search`）。已做去空格归一化（153→81 类），客户端调用 `filter.category` 时务必对用户/枚举值做 `strip()`。
7. **详情接口路径是坑**：单条详情走 `GET /openapi/v1/mcp/servers/<id>`（复数 `servers`）；`/openapi/v1/mcp/server/<id>`（单数）实测 **404**。详情直接回传 `server_config`（command + args），**这是安装唯一可靠来源**。

## 四、错误码与异常处理（列表）

统一结构：`{"success":false,"request_id":"...","code":"<错误码>","message":"<说明>"}`。

| HTTP | code | message（样例） | 触发条件 | 客户端应对 |
| :--- | :--- | :--- | :--- | :--- |
| 401 | `InvalidAuthentication` | `Invalid authentication: invalid or expired token` | token 无效/过期 | 检查 `Authorization: Bearer <token>` |
| 403 | `QuotaLimitExceed` | `Quota limit exceeded: ...` | `page_size>100` 或 `page_number×page_size>100`（匿名） | 钳制 page_size≤100；翻页需有效 token；遇 403 停止翻页 |
| 200 | — | （正常） | `filter.tag` 任意值 | 忽略 tag 过滤结果，勿依赖 |
| 404 | — | `404 page not found` | 用了 GET 等方法 | 必须用 PUT |

## 九、对接推荐架构 / 交付物 / 最佳实践

### 9.1 推荐架构

服务端已支持 `search`/`category`/`is_hosted` 过滤，所以**查询可直接走实时 API**（优于 skills 接口的纯客户端索引模式）：

```
应用 ──(PUT Body: search/filter/category/is_hosted)──▶ ModelScope API
        │                                               │
        │  匿名：仅第1页(≤100)                           │ 返回 mcp_server_list + total_count
        │  token：完整翻页                               ▼
        └──────────── 本地缓存/索引（可选，加速 & 离线浏览）
```

- **实时模式**（推荐对接主路径）：组装 Body → PUT → 解析 `mcp_server_list` 与 `total_count`。带 token 可翻页。
- **离线索引模式**（浏览/分析）：用本交付物的 `mcp_servers_index.jsonl`（3589 条）做全量客户端过滤、排序、分页，免 token、免配额。
- **分类枚举**：前端下拉直接用 `mcp_categories.json`（81 类，含计数）；调用 `filter.category` 前对值做 `strip()`。

### 9.2 调用示例

```bash
# curl（带 token 翻页）
curl -s -X PUT "https://www.modelscope.cn/openapi/v1/mcp/servers" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ms-xxxxxxxxxxxxx" \
  -d '{"page_number":2,"page_size":100,"filter":{"category":"search"}}'
```

```python
import json, urllib.request

def list_servers(page=1, size=100, token=None, **flt):
    body = {"page_number": page, "page_size": size}
    f = {k: v for k, v in flt.items() if v is not None}
    if f: body["filter"] = f
    data = json.dumps(body).encode()
    headers = {"Content-Type": "application/json"}
    if token: headers["Authorization"] = "Bearer " + token
    req = urllib.request.Request(
        "https://www.modelscope.cn/openapi/v1/mcp/servers",
        data=data, headers=headers, method="PUT")
    with urllib.request.urlopen(req, timeout=40) as r:
        d = json.loads(r.read())
    return d["data"]["mcp_server_list"], d["data"]["total_count"]

servers, total = list_servers(category="search", is_hosted=True)
print("命中", total, "个")
```

### 9.4 最佳实践 & 注意事项

1. **必须 PUT，必须 Body**：用 GET 会 404。
2. **`filter.tag` 不要用**：服务端未实现，返回全部。
3. **`filter.category` 先 `strip()`**：源数据分类带前导空格，否则命中不到。
4. **配额**：匿名口径下 `page_number × page_size ≤ 100`，超出即 `403 QuotaLimitExceed`；翻页需有效 token，遇 403 立即停止。
5. **`total_count` 可信**：可直接用于分页计算（与 skills 接口相反）。
6. **生产带 token**：匿名仅第 1 页，且平台可能随时收紧匿名访问。
7. **索引为快照**：`mcp_servers_index.jsonl` 是 2026-08-16 采集，重跑 `collect_mcp.py` 可刷新。
8. **容错**：判 `success` + HTTP 状态码；`401` 校验 token，`403` 停翻页。
